1. [Important · Bugs] `app/app.js:50` **Rename edits the wrong item when a filter is on** `i` is the item's position in `visible()`, but `rename()` uses it to index the full `todos` array. With the 'Chưa xong' or 'Đã xong' filter on, renaming the 1st visible item changes whatever item is 1st in the whole list. The user's other item is silently renamed and saved. → Pass the id instead (`rename(t.id, input.value)`) and look the item up with `todos.find((x) => x.id === id)`, the same way `toggle` and `remove` do. Add a test that renames an item while a filter is on.
2. [Important · Bugs] `app/app.js:24` **Rename message hides a failed save** `commit()` shows the result from `persist()`, which can say the save failed or was skipped after a read error. `rename()` then overwrites `#message` with 'Đã đổi tên…', so the user is told it worked when it was never saved. This breaks policy-ux@2#U1. → Show the rename message only when `persist` succeeded, or keep the persist message when it reports a problem (for example, have `commit()` return the persist result and check it).
3. [Important · Security] `app/app.js:24` **User text rendered with innerHTML** `t.title` is user text and is put into the page with `innerHTML`. A title like `<img src=x onerror=...>` runs script, and one stored via import runs again every time it is renamed. This breaks policy-security#S3. → Build the message with `textContent`, for example create a `<b>` element, set its `textContent` to the title, and append it, or simply call `show(`Đã đổi tên thành ${t.title}`)`.
4. [Important · Compliance] `app/app.js:21` **Confirm dialog on a single-item action, no Undo** policy-ux@2#U2 says actions on one item happen at once with no confirmation dialog and offer Undo for 10 seconds. The PR uses a native `confirm()` and has no Undo. → Remove the `confirm()`. Rename at once and offer 'Hoàn tác' for 10 seconds that restores the old title.
5. [Important · Bugs] `app/app.js:57` **Rename can't be started from the keyboard** Rename only starts on `dblclick` on a plain `<span>`, which can't take keyboard focus. Keyboard and screen-reader users can't rename at all, which breaks policy-ux@2#U5. The 'Nhấp đúp để đổi tên' hint is a `title` tooltip, so those users don't get it either. → Add a focusable control, for example a 'Đổi tên' button with an aria-label, or make the title focusable and start editing on Enter/F2.
6. [Nit · Compliance] `app/app.js:19` **New behaviour has no tests** The diff adds rename but no test in `tests/` (`app.test.js` can run `app.js` in a vm). A test would have caught the filter-index bug. The count is still 44. → Add tests to `tests/app.test.js`: rename saves the new title, Escape changes nothing, and renaming works with a filter on.
7. [Nit · Bugs] `app/app.js:62` **Edit box stays open on blur; empty Enter does nothing** Clicking away leaves the input open until the next render. Pressing Enter with an empty name does nothing and says nothing, so the user doesn't know why. → On `blur`, save or cancel (pick one and keep it consistent). On an empty name, either cancel or show a short message.
