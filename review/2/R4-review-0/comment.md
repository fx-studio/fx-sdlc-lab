1. [Important · Bugs] `app/app.js:50` **With a filter on, rename changes the wrong todo** `i` is the item's position in `visible()`, but `rename` looks it up in the full `todos` array. Suppose the 'Chưa xong' or 'Đã xong' filter is on and some items are hidden. If a user renames the 2nd visible item, the 2nd item in the whole list gets the new title instead. The wrong todo is overwritten and saved, and the user is not told. → Pass the id, not the position: `rename(t.id, input.value)`. In `rename`, use `todos.find((x) => x.id === id)`, like `toggle` and `remove` do. Change `for (const [i, t] of visible().entries())` back to `for (const t of visible())`. Add a test in tests/app.test.js that renames an item while a filter is on.
2. [Important · Bugs] `app/app.js:24` **A failed save is hidden behind a 'renamed' message** `commit()` shows the result of `persist()`. That can be the 'save failed' or 'skipped after a read error' message. Right after that, `rename` replaces it with 'Đã đổi tên thành …'. When storage is full or unreadable, the user is told the rename worked, but it is lost on reload. This breaches policy-ux@2#U1. → Show the success text only when `persist` reports a save. For example, call `persist(store, todos)` in `rename` and choose the message from its result, the way the other actions use `show(...)`. Add a test with a store that fails to save.
3. [Important · Bugs] `app/app.js:57` **Rename can only start with a double-click, not the keyboard** The span cannot get focus and only listens for dblclick, so keyboard and screen-reader users cannot rename at all. While editing, a click elsewhere (blur) leaves the input open and nothing is saved. This breaches policy-ux@2#U5. → Add a control that can get focus, such as a 'Sửa' button with an aria-label, or a tabindex plus an Enter/F2 handler on the title. On blur, either save or cancel.
4. [Important · Security] `app/app.js:24` **The new title is put on the page with innerHTML (XSS)** `$('#message').innerHTML = `…<b>${t.title}</b>`` puts the user's text straight into HTML. A title like `<img src=x onerror=…>` runs script, and the title is saved, so it can also arrive in an imported backup. This breaches policy-security@1#S3. → Build the message with `textContent`. Either call `show(fill(MESSAGES.renamed, { title: t.title }))`, or create the `<b>` with `createElement` and set its `textContent`. Add a test that a title containing `<b>` appears as plain text.

[Important · Compliance] `app/app.js:21` **Asks for confirmation on a single-item action** `confirm('Đổi tên việc này?')` asks before changing one item. policy-ux@2#U2 says actions on a single item run at once and offer Undo for 10 seconds instead of a confirmation. The native `confirm()` is also not the app's own `#confirm` dialog. → Remove the `confirm()`. Rename at once and offer Undo (restore the old title) for 10 seconds, as U2 requires.
