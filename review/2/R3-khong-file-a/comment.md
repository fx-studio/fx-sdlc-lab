# Review · PR 2 · generic, no REVIEW.md in repo · head bdf8458

1. `app/app.js:24` **** Security issue (policy-security@1#S3): the new title goes into the page through `innerHTML` (`Đã đổi tên thành <b>${t.title}</b>`). If someone renames a task to `<img src=x onerror=alert(1)>`, that code runs. The bad title is also saved in localStorage and exported in backups. Render it with textContent instead, e.g. build the `<b>` element and set its `.textContent = t.title`, or use `show(...)`.
2. `app/app.js:24` **** This line breaks policy-ux@2#U1. `commit()` has already called `show(persist(store, todos).message)`, and this line then replaces that message. When saving fails or is skipped after a read error, the save-failure message is overwritten with 'Đã đổi tên thành …'. The user is told the rename worked while it was never saved. Only show the rename message when persist actually succeeded.
3. `app/app.js:20` **** Wrong task gets renamed. `i` is the position in `visible()`, the filtered list, but `rename` looks it up in `todos[index]`, the full list. With the 'open' or 'done' filter on, renaming the 2nd shown task changes whichever task is 2nd in the full list. Pass `t.id` and look it up with `todos.find(x => x.id === id)`, the same way `toggle` and `remove` do.
4. `app/app.js:21` **** Breaks policy-ux@2#U2: actions on a single task must not ask for confirmation; they apply at once and offer Undo for 10 seconds. Also, `confirm()` is the browser's native dialog, not the app's `ask()` dialog. Remove the confirm and add Undo.
5. `app/app.js:57` **** Breaks policy-ux@2#U5: rename can only be started with a mouse double-click. The span cannot get keyboard focus and there is no key or button to start editing, so keyboard users cannot rename at all. Add a keyboard-reachable way to start it, such as a focusable rename button or Enter/F2 on a focusable title.
6. `app/app.js:63` **** Some edit cases are not handled. Clicking away (blur) leaves the input open with nothing saved and nothing cancelled. Pressing Enter on an empty or whitespace-only title does nothing and gives no feedback. Decide what blur should do (save or cancel) and tell the user when the name is empty.
7. `app/app.js:50` **** The PR says 44/44 tests, the same count as before, so no test covers the new behaviour. tests/app.test.js already runs app.js in a vm, so it can cover at least: rename by double-click then Enter, Esc cancels, renaming with a filter on changes the right task, and a title containing HTML is shown as plain text. Tests for the filter and HTML cases would have caught the two bugs above.
8. `review/2/PR.md:None` **** Calling this Small is fine (one file), but it adds a new user-facing behaviour and the rules it has to follow (S3, U1, U2, U5) were not checked before coding. 'Base: main (04ee584)' does not match the actual base commit b6712a1 (b6712a1's message says 'snapshot of 04ee584'), so the PR description should say which one it means.
