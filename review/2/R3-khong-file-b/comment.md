# Review · PR 2 · generic, no REVIEW.md in repo · head bdf8458

1. `app/app.js:25` **** XSS and a policy-security@1#S3 violation. The title is user text and goes into the page through `innerHTML` (`Đã đổi tên thành <b>${t.title}</b>`). If someone renames a task to `<img src=x onerror=alert(1)>`, that code runs. It also stays in localStorage and in backups, so an imported file can carry the same payload. Build the message with `textContent`, for example by creating the `<b>` element and setting its `textContent`, or simply call `show(...)`.
2. `app/app.js:50` **** Wrong task gets renamed. `i` is the index in `visible()`, but `rename()` uses it to look up `todos[index]`, which is the full list. With the 'open' or 'done' filter on, double-clicking the 2nd visible task can rename a different task, possibly a hidden one. Look the task up by `t.id` instead, the way `toggle`/`remove` do: `rename(t.id, input.value)` with `todos.find((x) => x.id === id)`.
3. `app/app.js:21` **** This breaks policy-ux@2#U2. A single-item action must not ask for confirmation; it should happen at once and offer Undo for 10 seconds. Renaming one task is a single-item action, so remove `confirm('Đổi tên việc này?')` and add Undo. `confirm()` is also a blocking native dialog. The app already has its own `ask()` dialog for the cases where confirming is required.
4. `app/app.js:24` **** A failed save gets hidden (policy-ux@2#U1). `commit()` already shows `persist(store, todos).message`. That message can say the save failed or was skipped, for example after a read error, when `save()` returns 'skipped'. The next line overwrites it with 'Đã đổi tên thành …', so the user is told the rename worked when nothing was saved. Show the success text only when the persist succeeded, or show both messages.
5. `app/app.js:57` **** Renaming only works with a mouse, which breaks policy-ux@2#U5 (every control works with the keyboard). The rename starts from `ondblclick` on a `<span>` that cannot get focus. Keyboard and screen-reader users can't rename at all, and the `title` hint is only visible on mouse hover. Add a focusable way to start editing, such as a 'Đổi tên' button with an aria-label, or make the span focusable and start editing on Enter/F2.
6. `app/app.js:63` **** Some edit paths are left unfinished. Enter on an empty or blank name does nothing and shows no message. Clicking elsewhere (blur) leaves the input open without saving or cancelling. Any later `render()`, for example after toggling another task, silently drops the edit. Decide what blur does (save or cancel), and say why an empty name is refused.
7. `app/app.js:19` **** No tests were added: the PR still reports `tests 44` / `pass 44`. `tests/app.test.js` already runs app.js in a `vm`, so the new behaviour can be tested. At least cover: renaming under an active filter (this would have caught the index bug), Esc cancels, the title is rendered as text and not HTML, and renaming during a read error. 'Small' size still needs a test that proves the change.
8. `review/2/PR.md:None` **** The PR describes the behaviour as 'Enter để lưu, Esc để thôi'. It doesn't mention the extra confirm() step, which goes against policy-ux. The description doesn't account for it. Also, the 'Base: main (04ee584)' in the description does not match the actual base commit b6712a1, which is a snapshot of 04ee584. Worth checking that the base is right.
